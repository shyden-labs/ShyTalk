# Plan 1 of 12: the throwaway spike — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove or disprove, on Shyden's real devices, the six risky parts the
approved design rests on, and record measurements that plans 2-12 are written
from.

**Architecture:** One throwaway Expo SDK 58 dev-build app plus one throwaway
Cloudflare Worker (with a Durable Object and a D1 database) on the DEV
Cloudflare account, plus a LiveKit server run locally on the Mac in `--dev`
mode. None of this code is kept: it lives in a local-only folder that is never
pushed and never merged anywhere. What's kept is the results file.

**Tech Stack:** Expo SDK 58 (React Native 0.88), TypeScript, `@expo/app-integrity`
(alpha), `@livekit/react-native` 3.x + `@livekit/react-native-webrtc`,
`expo-notifications`, Cloudflare Workers + Durable Objects + D1 (Wrangler),
`livekit-server --dev`.

**Spec:** [`../specs/2026-10-24-shytalk-rewrite-design.md`](../specs/2026-10-24-shytalk-rewrite-design.md)
(approved, decision 96). Sections used: 4.1 (spike list), 4.4, 4.6, 4.8 (voice
evidence), 4.13, 4.14, 3 (free limits).

## Global Constraints

- **Throwaway.** All spike code lives in `~/Developer/Repos/shytalk-spike/`, a local git repo
  that's never given a remote and never pushed. Keeping any of it later needs a
  new request (brainstorming hard gate).
- **No TDD for spike code** (it's thrown away). Each task's "test" is a
  measurement with a pass line, written to the results file. A pass is claimed
  only from a measured run on a real device, never from a simulator, emulator
  or reasoning.
- **Free only.** Dev Cloudflare account on the Workers Free plan. LiveKit runs
  on the Mac. No paid service, and nothing on a timer.
- **Devices (decision 94):** iPhone Duo (folded and unfolded), iPad, Android
  tablet or foldable, Android phone with Google, phone without Google, plus
  Shyden's existing iPhone and Android phones. The iOS simulator and the
  Android emulator are used ONLY as the "must be refused" cases in Task 2.
- **Shyden does these by hand** (agents act as the App, never as him): sign in
  to Wrangler on the dev account, sign iOS dev builds with his Apple team, add
  the spike to Play Console internal testing, give the Google Cloud project
  number. Each one is asked for with one copyable command or click path.
- **Results file:** `~/Developer/Repos/ShyTalk/.superpowers/sdd/REWRITE/spike-results-2026-10.md`.
  One section per task. Each section holds: the device, build or commit, the
  command, the measured numbers, PASS/FAIL against the pass line, and what it
  changes in later plans.
- **Nothing touches production**, the old repo's code, or the old Firebase
  project.

## Review Focus

1. **A pass measured on only one phone.** Every pass line names both iPhone
   and Android. A one-sided result is recorded as FAIL-PARTIAL, never PASS.
2. **Fold, unfold and Split View while a voice room is live.** A reflow must
   not drop the voice connection or the typed text (Task 1 + Task 3, combined
   check in Task 3 step 4).
3. **Phone call mid-room.** The mic pauses and comes back. The person stays in
   the room (design 4.6) (Task 3 step 3).
4. **App killed while the voice clip buffer is full.** Nothing is left on disk
   (Task 4 step 4).
5. **Free-limit counting.** Requests per user action are counted from
   Cloudflare's own analytics, not guessed (Task 5 step 4).

### Task 4: Last-minute voice clip on the phone (decision 92)

**Files:** `~/Developer/Repos/shytalk-spike/modules/voice-clip/` (a local Expo module, Swift + Kotlin).

**Interfaces:** Produces for plan 6 the route that works:
`startClipBuffer(seconds: 60): void`, `takeClip(): Promise<{ uri: string;
durationMs: number }>`, `stopClipBuffer(): void`.

No official LiveKit React Native API reads remote-track PCM (searched
2026-10-24). Try these routes in order and record each one:
(a) any LiveKit RN audio-renderer API in the installed version;
(b) a native sink on the WebRTC remote audio track (Android `AudioTrack.addSink`
in org.webrtc; iOS `RTCAudioRenderer` on the remote `RTCAudioTrack`);
(c) a fallback, if neither works: at report time the server starts LiveKit
egress for that room. This captures from the report onwards, not the minute
before it, so it's recorded as a design change for Shyden, never adopted
silently.

- [ ] **Step 1:** Try route (a), then (b), on iPhone and Android. Record what
  each exposes: sample rate, channels, whether frames are per participant.
- [ ] **Step 2:** Keep a 60 s ring buffer in memory (not on disk) of the mixed
  remote audio. Record the resident memory added after 10 minutes in a room
  (Xcode Instruments / Android Studio profiler).
- [ ] **Step 3:** `takeClip()` writes the last 60 s to a temp file and plays it
  back. Pass: the clip is 60 s ± 1 s and every speaker can be heard, on both
  phones.
- [ ] **Step 4:** Kill the app with the buffer full, then relaunch. Pass: no clip
  or audio file exists in the app's storage (list the container).
